# 脅威と対策（Threat model）

対象：自治体・大学の窓口業務の件数データを、閉域のPCで分析し、LLMに要約させる用途。

| 脅威 | 起き方 | 対策 | 確かめ方 |
|---|---|---|---|
| LLMが数値を作る（ハルシネーション） | 要約に集計結果と異なる数値が書かれる | LLMには数値を直接書かせず、指標ID（`{M3}`）で参照させ、値はコードが差し込む。数字の直書き・漢数字は違反 | `evals/run_evals.py`（直書き・漢数字の検出率） |
| 指標の取り違え | 「期末」と書いた文で「最大」の値を参照する | 参照した文に、その指標を表す語（業務名・期末・最大など）がすべて含まれるかを検査 | 同じ単位の全組み合わせの差し替え評価 |
| 違反した要約の採用 | 再生成しても違反が残る | 1回だけ違反内容を添えて再生成し、残れば決まった文型に切り替えてLLMの要約を採用しない | `tests/test_basic.py`、評価の「最終報告から除外」 |
| プロンプトインジェクション | CSVの業務名に「以下の指示を無視して…」などを入れる | 指示文とみられる語・使えない文字を含む行を読み込み時に拒否 | 評価の「業務名に混ぜた指示文を拒否」 |
| 個人情報の外部送信 | 質問や名前にメールアドレス・電話番号が含まれる | LLMへ送る前に検出し、送信しない（計画・要約の両方） | `tests/test_basic.py` |
| 外部のAIサービスへの送信 | 設定の誤りで外部のURLを指定する | 接続先を許可ホストに限定し、転送も追わない | `tests/test_basic.py` |
| MCP経由の任意ファイルの読み取り | `../../etc/passwd` などを指定する | 許可フォルダ・拡張子・大きさで制限 | 評価の「MCPで許可外のファイルを拒否」 |
| SQLインジェクション | 業務名などにSQLを混ぜる | SQLはすべてプレースホルダで値を渡す。スキーマにCHECK制約と一意制約 | `jissoku/store.py` |
| 集計の誤り | 計算の不具合 | SQLの集計とPythonの集計を突き合わせる検算、未処理件数の収支の検算 | `python -m jissoku.store reconcile`、単体テスト |
| 記録の改ざん | 承認後に監査ログを書き換える | ハッシュチェーンで、書き換え・削除を検出 | `python -m jissoku.audit verify` |

## 残っている制約
- 個人名の検出はしていません。区分には個人名を入れない運用を前提にしています。
- 取り違えの検出は、文中の語による判定です。差し替え先の指標を表す語がすべて同じ文に含まれる場合は検出できません。
